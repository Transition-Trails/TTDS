FOUND 5 AUGUST

The trail field on Contact holds two different formats

Five learners carry a trail value, and it is recorded three ways: one as a hyphenated identifier, two as display labels. The trail configurations are keyed on hyphenated identifiers.

explorer-journey — 1 learner, matches a configuration
Guided Trail — 3 learners, no match
Trail of Mastery — 1 learner, no match

The consequence is that Penny's trail context layer silently fails for four of five learners. A learner whose trail reads as a label finds no configuration, so Penny answers them without knowing their programme, their phase or her role for that trail — and nothing reports a problem, because an absent layer is a normal condition.

Two fixes, and both are worth doing. Normalise the existing values so every learner resolves. Then constrain the field, because a free-text or loosely-valued trail will drift again — and this is the third time a value mismatch has produced a silent failure rather than an error.

Resolved — per-learner progress lives on two objects the workbook never listed

Settled 4 August. The missing parent object turned out not to matter: production already carries a course enrolment object and an activity completion object, and the completion object is where a learner's own progress lives. The assignments query has been rebuilt onto it.

One structural detail worth keeping: the link runs enrolment to completion, not contact to completion. There is also a denormalised contact field on the completion object, which is what makes a per-learner query possible without a join.

Neither object carries a due date. The endpoint now reports that plainly so the interface can suppress the column rather than render blanks. If a due date is added later, the wiring point is marked in the code.

Resolved — learner identity comes from a Google group

Settled 4 August. A dedicated learner group will grant access to the learner surface, the same mechanism already driving staff access. Contact is still where a learner's record lives, but group membership is what makes someone a learner. This unblocks the live learner read model.

Cleanup — 3

Small, mechanical, and worth doing before the pattern spreads further. All three came in with the Penny dashboard on 5 August.

Type has dropped back below the floor

The new dashboard runs interface text at ten to thirteen pixels — badges, stat labels, table headers — against a fourteen-pixel floor. The contributor pack flagged this as the easiest standard to reintroduce, and it was reintroduced in the next release. Worth raising on this screen and considering whether the rule can be enforced rather than remembered.

Raw colour values are back

About a dozen hex values are written inline on the dashboard rather than referencing tokens. The values are correct — they are brand colours — so nothing looks wrong today. The cost is that the next palette change will miss this screen.

Amber also appears in three non-action roles on the same screen: the coach identity row, the needs-attention panel and the write-failure detail. None is a call to action, which is the rule it bends.

The changelog describes a metric that does not exist

The 1.4.0 entry describes an average satisfaction figure, per-audience satisfaction and satisfaction bars. None of it is in the code, and the code is right — no satisfaction is collected anywhere, so inventing the number would have been worse. Worth correcting the entry so nobody builds a report on a figure that was never captured.

Design not started — 3

Empty, loading, stale and failed states

The prototype has never needed them — stubbed data is always present, correctly sized and fresh. Thirteen objects are deployed and empty, so live data will be none of those things.

Four shared states designed once against the brand, rather than invented per screen as each one breaks. The validation page already proved the cost of not distinguishing them.

Coach view

Inside Trail OS, group-gated, desktop first, and organised around Penny drafting while the coach approves. A coach sees everything — no partitioning.

Open: how the three coach levels differ, and where a verdict is actually issued.

Learner view

Trail OS with Slack alongside as the communication layer, likely in a side panel. Trail OS is where the work and coaching happen; Slack carries conversation, nudges and quest delivery.

Open: whether learners see each other's verdicts. Buddy testing requires some visibility; the rework curve is far more sensitive.

One thing to settle before either view is built

Because Trail OS and Slack are open at the same time rather than used in turn, Penny in each is one conversation with two windows. Her memory must be keyed on the person, not the surface — otherwise a learner asks something in Slack, turns to Trail OS, and finds she has forgotten it.
